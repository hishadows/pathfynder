- 2026-09-26 — Added the bare `/explore` landing flow (no from/to in the URL): search panel + skeleton render immediately and a BROWSE search (`explore_search` with all coords null) runs right away. If geolocation permission is already granted it's used automatically for a NEAR ME search (25 km radius, `p_o_lat/p_o_lng` set, `p_d_lat/p_d_lng` null); otherwise a "See rides near you" card (reusing `.prefill` styling) lets the user opt in, denial/timeout falls back to a plain BROWSE hint instead of an error. Nearest town is computed client-side via haversine over `places` (`popularity >= 20`) and used for the heading + to prefill From. Mode toggle and filters re-run whichever of NEAR ME/BROWSE is active; picking both From and To switches to the existing matched search unchanged, clearing them returns to landing. Coordinates never leave memory except in the `explore_search` call. Verified with `node --check`. Files: explore.html.

Default sources is now all three (`whatsapp`,`poparide`,`facebook`); added a "Ride type" section (Urgent/Airport/Daily chips) to the Filters sheet; added matching card tags for `is_urgent`/`is_airport`/`is_daily`. `?debug=1` logs every `explore_search` payload + row count.

  - **Location popup rebuilt** as a bottom sheet: silent on already-granted permission; a "See rides near you" sheet on prompt/unsupported (Allow/Not now, sessionStorage-suppressed after dismissal); a "Location is blocked" sheet with per-platform steps on denied (shown once per session); a small "Use my location" entry point reopens the right sheet.   - Updated CLAUDE.md with the new `explore_search` fields/filter keys, `submit_group_link`, and the Mapbox v6 + places-fallback rule.

- 2026-09-26 — Added auto-refresh so new WhatsApp posts appear without reloading: every 60s, while the tab is visible and no sheet is open, `backgroundRefresh()` silently re-runs whichever search is active (matched / near-me / browse) with the same params — no skeleton, no re-render. If the refreshed rows include any id not in the current list, they're stashed in `state.pendingRows` and a "↑ N new rides" pill (reusing `.btn-text`/chip-soft styling) is inserted at the top of the list; tapping it applies the new rows and scrolls to top. Coming back to a hidden tab after more than 60s triggers an immediate refresh. The timer stops on `visibilitychange` → hidden and a `refreshInFlight` flag prevents overlapping requests. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fixed 4 /explore bugs:
  - **Date chips broken on mobile**: the calendar chip relied on `input.showPicker()`/`.click()` on a 1×1px `pointer-events:none` date input, which iOS Safari and in-app browsers (WhatsApp/Instagram) don't reliably support. Replaced it with a real `<input type="date">` absolutely positioned over the (now decorative, `pointer-events:none`) chip, `font-size:16px` so iOS doesn't zoom, listening to both `change` and `input`. Today/Tomorrow were already plain click handlers (no picker) and needed no change. Added `?debug=1` logging for every date-chip tap.
  - **Location auto-popup removed**: `checkGeoPermission()` no longer opens any sheet on its own — it only sets `state.loc.status` so the small "Use my location" entry point can appear. That button now calls `getCurrentPosition()` directly; success runs a near-me search, `PERMISSION_DENIED` opens the existing "Location is blocked" sheet (copy now also covers in-app browsers: "tap ⋯ → Open in Safari/Chrome, then allow location"), any other error/timeout shows a toast instead.
  - **State lost on refresh**: the URL now round-trips `type`/`from`/`to`/`date`/`time`/`flex`/`sort` and the filters (`src`, `match`, `tod`, `rt`, `v`, `nb`, `lug`) via `history.replaceState` on every render; a near-me session stores only `near=1` (never coordinates). Selected from/to place objects are cached in `sessionStorage` (`pf_explore_places`) so a reload skips re-resolving them, falling back to the `places` lookup when the cache misses. Filters are read from the URL into `state.filters` before the very first search runs.
  - **Filters sheet jumped to top on every tap**: chip/toggle/radio taps in the Filters and Time sheets now mutate the tapped element's class/style/`aria-checked` in place instead of replacing `#sheetBody` innerHTML; only Reset/Clear all (a full sheet reset) still re-renders, now saving and restoring `.sheet__body` scrollTop around it.
  - Restyled the WhatsApp group-link card to the new `.group-card` design (dashed border, icon + title/text head, stat pills, styled input/Paste row, primary "Add group" button, success/error result line, steps footer); logic (0-WhatsApp-rows trigger, `submit_group_link`, clipboard paste, 7-day localStorage hide) unchanged.
  - Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fixed explore_search never sending Today/Tomorrow date, time_of_day or exact time (confirmed from server logs: `p_date: null`, `p_filters` missing everything but `sources`). Root causes: (1) exact time was written to top-level `state.time`/`state.flex`, but `buildFilters()` reads `time`/`flexMin` off the filters object it's given, so it never saw them in any mode; (2) the near-me/browse search and the filters-count preview each had their own inline params object hardcoding `p_date: null`, ignoring `state.date` entirely; (3) Today/Tomorrow computed the date via `todayStr()`, which used the browser's local timezone instead of Toronto. Fix: exact time now lives in `state.filters.time`/`state.filters.flexMin` alongside the other filters; `rpcParams()` is the single request builder for every `explore_search` call site (matched, near-me, browse, filters-count preview) and always reads `state.date`/`state.filters`; Today/Tomorrow now use the existing `torontoTodayStr()` helper. All of it round-trips through the URL (from the earlier persistence fix) and `?debug=1` logs every final payload. Verified with a temp Node harness exercising Tomorrow, Morning+Evening, exact 6 PM ±1h, and Urgent+Verified — each produced the correct `p_date`/`p_filters` — and with `node --check`. Files: explore.html.
- 2026-09-26 — Three /explore changes:

Results show Mapbox POIs/addresses/cities first (up to 6, pin icon on POI rows) then up to 3 `places` rows not already present (deduped by name); silent places-only fallback on a missing/failing/401/403/429 token.   - **Search with From only, always**: picking a place for From now runs a near-from search immediately (`p_o_lat/lng` set, `p_d_*` null) whether or not To is filled; clearing To falls back to the same near-from search; clearing From falls back to browse/near-me. `runSearch()`/`rpcParams()`/`searchOrRender()` no longer require both From and To.
  - **Removed the location sheets** ("See rides near you" / "Location is blocked") entirely — geolocation is now only ever silent-on-already-granted or driven by the inline "Use my location" card, which switches in place to "Showing rides near you" on success or an inline blocked-with-steps message (covering in-app browsers) with a "Try again" text button on `PERMISSION_DENIED`.
  - Also restyled the WhatsApp group-link card to "Option A — chat invite" (WhatsApp-bubble look, composer-style input row, send button) replacing the dashed Option B card; same trigger/RPC/paste/7-day-hide logic.

- 2026-09-26 — Fixed 4 more /explore bugs (found from server logs + testing):
  - **Calendar chip overlay spilled onto the clock chip**: the transparent `<input type="date">` wrapper was missing `overflow:hidden`, and the input used the `inset:0` shorthand (unsupported in older WebKit / some in-app browsers), so on those it fell back to its native width and covered the neighboring clock chip. Added `overflow:hidden` to the wrapper and switched to explicit `top/right/bottom/left:0`.
  - **Time sheet "Set" button went stale**: the wheel's debounced `scroll` handler updated the "Rides leaving X – Y" summary but never the footer's "Set …" button text. Extracted the shared label logic into `setLabel()`/`updateTimeSheetLabels()`, called from the flex-chip handler (previously the only place that updated both) and now also from the wheels on every `scrollend` (with the existing 120ms debounced `scroll` kept as a Safari fallback). Opening the sheet with no saved time now scrolls to the next full hour (`nextFullHour()`) instead of a hardcoded 6:00 PM.
  - **Past dates could reach the RPC**: an old URL or manually-typed date bypassing the picker's `min` is now clamped to today (`torontoTodayStr(0)`) inside `rpcParams()` — the one function every search funnels through — resetting the date chip to "Today".
  - **From location lost on a second, coordinate-less request**: `buildFilters()` now takes the origin/destination place objects as arguments (`originPlace`/`destPlace`) instead of re-reading `state.fromPlace`/`state.toPlace` itself, so `from_name`/`to_name` are always derived from the exact same object `rpcParams()` used for `p_o_lat/p_o_lng`. The From/To inputs' `change` handler no longer clears the picked place just because the field loses focus with unchanged text; it only clears it (and marks the text unresolved) when the typed value actually differs from the picked place's name, and clears it outright when the field is emptied. `?debug=1` now logs each request's sequence number alongside its params.
  - Verified with `node --check`. Files: explore.html.

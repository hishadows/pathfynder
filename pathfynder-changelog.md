# Pathfynder Changelog

- 2026-09-26 — Added CLAUDE.md (project + /explore rules)
- 2026-09-26 — Built /explore (Explore Rides) page from design/explore-mockup.html v3: search panel, filters sheet, exact-time sheet, ride cards + detail sheet, swipe-to-original-message, empty/loading/error states. Wired to Supabase (`places` autocomplete, `explore_search`/`explore_contact` RPCs) with a local mock fallback (explore-mock.js) until explore_search ships. Files: explore.html, explore-mock.js, vercel.json (cleanUrls + build copy), CLAUDE.md (final RPC contract).
- 2026-09-26 — Fixed a production JS syntax error in explore.html: an unescaped apostrophe in `we don't have yet` broke a single-quoted string in `emptyState()` (line 914), throwing `Unexpected identifier 't'` and blanking the whole page. Switched that string to double quotes; scanned the rest of the inline `<script>` for the same issue (none found) and verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fixed /explore deep links never searching when the place name doesn't exactly match `places.name` (e.g. "St Catharines" vs "St. Catharines"). `resolvePlace()` and the autocomplete query now match on `places.norm_key` (via a new `normPlace()` helper) with a `popularity`-ranked prefix fallback, and display the matched `name` back in the inputs. If a from/to still can't be resolved, the page now falls back from the prefill bar to the search panel with a "Couldn't find "<name>" — pick it from the list" note instead of silently showing nothing. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Added the bare `/explore` landing flow (no from/to in the URL): search panel + skeleton render immediately and a BROWSE search (`explore_search` with all coords null) runs right away. If geolocation permission is already granted it's used automatically for a NEAR ME search (25 km radius, `p_o_lat/p_o_lng` set, `p_d_lat/p_d_lng` null); otherwise a "See rides near you" card (reusing `.prefill` styling) lets the user opt in, denial/timeout falls back to a plain BROWSE hint instead of an error. Nearest town is computed client-side via haversine over `places` (`popularity >= 20`) and used for the heading + to prefill From. Mode toggle and filters re-run whichever of NEAR ME/BROWSE is active; picking both From and To switches to the existing matched search unchanged, clearing them returns to landing. Coordinates never leave memory except in the `explore_search` call. Verified with `node --check`. Files: explore.html.

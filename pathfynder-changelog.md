# Pathfynder Changelog

- 2026-09-26 — Added CLAUDE.md (project + /explore rules)
- 2026-09-26 — Built /explore (Explore Rides) page from design/explore-mockup.html v3: search panel, filters sheet, exact-time sheet, ride cards + detail sheet, swipe-to-original-message, empty/loading/error states. Wired to Supabase (`places` autocomplete, `explore_search`/`explore_contact` RPCs) with a local mock fallback (explore-mock.js) until explore_search ships. Files: explore.html, explore-mock.js, vercel.json (cleanUrls + build copy), CLAUDE.md (final RPC contract).
- 2026-09-26 — Fixed a production JS syntax error in explore.html: an unescaped apostrophe in `we don't have yet` broke a single-quoted string in `emptyState()` (line 914), throwing `Unexpected identifier 't'` and blanking the whole page. Switched that string to double quotes; scanned the rest of the inline `<script>` for the same issue (none found) and verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fixed /explore deep links never searching when the place name doesn't exactly match `places.name` (e.g. "St Catharines" vs "St. Catharines"). `resolvePlace()` and the autocomplete query now match on `places.norm_key` (via a new `normPlace()` helper) with a `popularity`-ranked prefix fallback, and display the matched `name` back in the inputs. If a from/to still can't be resolved, the page now falls back from the prefill bar to the search panel with a "Couldn't find "<name>" — pick it from the list" note instead of silently showing nothing. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Added the bare `/explore` landing flow (no from/to in the URL): search panel + skeleton render immediately and a BROWSE search (`explore_search` with all coords null) runs right away. If geolocation permission is already granted it's used automatically for a NEAR ME search (25 km radius, `p_o_lat/p_o_lng` set, `p_d_lat/p_d_lng` null); otherwise a "See rides near you" card (reusing `.prefill` styling) lets the user opt in, denial/timeout falls back to a plain BROWSE hint instead of an error. Nearest town is computed client-side via haversine over `places` (`popularity >= 20`) and used for the heading + to prefill From. Mode toggle and filters re-run whichever of NEAR ME/BROWSE is active; picking both From and To switches to the existing matched search unchanged, clearing them returns to landing. Coordinates never leave memory except in the `explore_search` call. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fix + extend /explore for the new backend contract:
  - **Filters now all work**: every filter change (chips, toggles, sheet Reset/Clear all/✕ removal) rebuilds `p_filters` (added `urgent`/`airport`/`daily` keys) and re-runs whichever search is active (matched / near-me / browse) via a shared `searchOrRender()`. Default sources is now all three (`whatsapp`,`poparide`,`facebook`); added a "Ride type" section (Urgent/Airport/Daily chips) to the Filters sheet; added matching card tags for `is_urgent`/`is_airport`/`is_daily`. `?debug=1` logs every `explore_search` payload + row count.
  - **Date picker**: hidden `<input type=date>` now gets `min` = today in Toronto time and stays in sync with `state.date`; undated rows (`ride_date` null) show "Date not given" / "Time flexible" instead of crashing `dayLabel()`.
  - **Fixed external links not opening on mobile**: `contact()` now opens `about:blank` synchronously in the click handler for Poparide/Facebook rows, before the `explore_contact` await, then redirects that tab — mobile browsers were blocking `window.open()` called after the await.
  - **Fixed "$$30" price bug**: card and detail views now render from the numeric `price_num` field instead of prepending "$" to the already-formatted `price` text.
  - **Sort correctness**: Best match keeps server order (stable, no reorder); Soonest sorts by `ride_date` then `ride_time` (nulls last); Cheapest sorts by `price_num` (nulls last, ties broken by Soonest). Unparsed posts stay in their own section regardless of sort.
  - Passenger-mode "all along-route" info line now reads "No direct passengers…" instead of the driver-mode copy.
  - **Autocomplete**: merges up to 3 `places` matches with Mapbox Geocoding API v6 forward results (3+ chars, 300ms debounce, `AbortController`), deduped by name; silently falls back to places-only on a missing/failing/401/403/429 Mapbox token. Deep-link resolution stays places-first, with one Mapbox call only when places finds nothing.
  - **WhatsApp group-link card**: shown as the first list card (styled like `.ride-card`) whenever the current results have 0 WhatsApp rows, including the empty state. Submits via the new `submit_group_link` RPC; ok/duplicate collapses the card and hides it for 7 days (`localStorage: pf_group_card_done`).
  - **Location popup rebuilt** as a bottom sheet: silent on already-granted permission; a "See rides near you" sheet on prompt/unsupported (Allow/Not now, sessionStorage-suppressed after dismissal); a "Location is blocked" sheet with per-platform steps on denied (shown once per session); a small "Use my location" entry point reopens the right sheet. Never auto-opens when from/to are in the URL.
  - Updated CLAUDE.md with the new `explore_search` fields/filter keys, `submit_group_link`, and the Mapbox v6 + places-fallback rule.
  - Verified with `node --check`. Files: explore.html, CLAUDE.md.
- 2026-09-26 — Allowed swipe-to-original-message on Poparide passenger requests: the swipe condition (`renderRideCard`) now only checks `r.raw_text` truthiness, not source — Poparide driver offers still have `raw_text = null` from the RPC so they're unaffected. Detail sheet's description block now reads "From the rider" for passenger rows ("From the driver" unchanged for drivers); the "Original message" bubble was already WhatsApp-only, so Poparide rows still show the description once, not twice. `messagePane()`/`ride_time` needed no changes — they already read `posted_at`/`ride_time` generically regardless of source. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Added auto-refresh so new WhatsApp posts appear without reloading: every 60s, while the tab is visible and no sheet is open, `backgroundRefresh()` silently re-runs whichever search is active (matched / near-me / browse) with the same params — no skeleton, no re-render. If the refreshed rows include any id not in the current list, they're stashed in `state.pendingRows` and a "↑ N new rides" pill (reusing `.btn-text`/chip-soft styling) is inserted at the top of the list; tapping it applies the new rows and scrolls to top. Coming back to a hidden tab after more than 60s triggers an immediate refresh. The timer stops on `visibilitychange` → hidden and a `refreshInFlight` flag prevents overlapping requests. Verified with `node --check`. Files: explore.html.
- 2026-09-26 — Fixed 4 /explore bugs:
  - **Date chips broken on mobile**: the calendar chip relied on `input.showPicker()`/`.click()` on a 1×1px `pointer-events:none` date input, which iOS Safari and in-app browsers (WhatsApp/Instagram) don't reliably support. Replaced it with a real `<input type="date">` absolutely positioned over the (now decorative, `pointer-events:none`) chip, `font-size:16px` so iOS doesn't zoom, listening to both `change` and `input`. Today/Tomorrow were already plain click handlers (no picker) and needed no change. Added `?debug=1` logging for every date-chip tap.
  - **Location auto-popup removed**: `checkGeoPermission()` no longer opens any sheet on its own — it only sets `state.loc.status` so the small "Use my location" entry point can appear. That button now calls `getCurrentPosition()` directly; success runs a near-me search, `PERMISSION_DENIED` opens the existing "Location is blocked" sheet (copy now also covers in-app browsers: "tap ⋯ → Open in Safari/Chrome, then allow location"), any other error/timeout shows a toast instead.
  - **State lost on refresh**: the URL now round-trips `type`/`from`/`to`/`date`/`time`/`flex`/`sort` and the filters (`src`, `match`, `tod`, `rt`, `v`, `nb`, `lug`) via `history.replaceState` on every render; a near-me session stores only `near=1` (never coordinates). Selected from/to place objects are cached in `sessionStorage` (`pf_explore_places`) so a reload skips re-resolving them, falling back to the `places` lookup when the cache misses. Filters are read from the URL into `state.filters` before the very first search runs.
  - **Filters sheet jumped to top on every tap**: chip/toggle/radio taps in the Filters and Time sheets now mutate the tapped element's class/style/`aria-checked` in place instead of replacing `#sheetBody` innerHTML; only Reset/Clear all (a full sheet reset) still re-renders, now saving and restoring `.sheet__body` scrollTop around it.
  - Restyled the WhatsApp group-link card to the new `.group-card` design (dashed border, icon + title/text head, stat pills, styled input/Paste row, primary "Add group" button, success/error result line, steps footer); logic (0-WhatsApp-rows trigger, `submit_group_link`, clipboard paste, 7-day localStorage hide) unchanged.
  - Verified with `node --check`. Files: explore.html.

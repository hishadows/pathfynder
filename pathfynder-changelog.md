- 2026-09-27 — Fixed a false "Couldn't load rides" error on /explore and made rides always show regardless of location. **Root cause (confirmed against Supabase logs — every `explore_search` call at 13:39–13:41 UTC returned HTTP 200, yet the page showed the error)**: `runSearch()`/`performLandingSearch()` called `render()` (which builds every ride card's HTML) *inside* the same `.then()` that handled a successful RPC response, with a single `.catch()` after it. A single malformed row throwing while building its card was therefore caught by that same `.catch()` and misreported as a network failure, wiping `state.rows` and showing the error card even though the RPC had already returned data. The logged "pairs of identical calls at the same millisecond" pointed at a second contributing issue: no de-duplication, so a duplicate in-flight request could fire and its stale response processed as if it were the latest.

Every call gets an incrementing request id (existing `searchSeq`, now consistently checked on both success and failure); identical in-flight params are de-duped (`searchInFlightKey`) instead of firing a second request; a newly-started search aborts the previous one via `AbortController`/`.abortSignal()` where supported, and an aborted/superseded result is now silently ignored rather than shown as an error. "Couldn't load rides" now only appears for a real RPC/network failure, which is still `console.error`'d.
  - **Removed all location-asking UI**: deleted `locationCard()` ("See rides near you" / "Uses your location once — never saved" / "Use my location" banner and the "Location is blocked" retry card) and its `js-use-location`/`js-loc-retry` click handlers — no more in-page location prompts or banners of any kind.

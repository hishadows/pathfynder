Wiring notes

  • Each screen is a config in APPS rendered by renderApp(config). Cards come from renderRideCard(ride): source, parsed, role and business pick the variant (.ride-card--whatsapp|poparide|facebook, --raw, --request, --business). Swap RIDES for the matching RPC's rows.
  • Matching fields per row: match.type (direct | near), match.pickup_km, match.dropoff_km, and an optional match.strip (point % positions + segment km) for the detail sheet. Rows come back already ranked: direct, then near, with business rows pushed last.
  • Every value sits on a data-field attribute named after its column (depart_time, arrive_time, seats, price_per_seat, rating, verified, luggage, recurring, via, rider_tag, is_business, description, group_names). An empty optional field renders no element at all.
  • Driver mode shows poster_name as first name + last initial (“Harleen K.”). Format it server-side so the full name never reaches the client.
  • Duplicate WhatsApp posts are merged before render: one row with group_names[]. The card shows “Posted in N groups”, and the sheet lists each group.
  • The WhatsApp CTA is wa.me/<wa_number>?text=… with a ready-to-send message. The number never renders in the UI.
  • The green CTA uses dark text (#111B21) on #25D366 / #00A884, because white on #25D366 fails contrast.
